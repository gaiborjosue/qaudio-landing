# Q Audio

A monochrome hi-fi storefront prototype for Q Audio in Cambridge, Massachusetts. The landing experience, category exploration, brand destinations, contact dialog, visit section with live store hours, contact footer, the news feed with its migrated posts, and the QDeal page with its Supabase-managed deals are implemented. Shop destinations are collection placeholders; product inventory, checkout, and backend message delivery are not implemented.

## Setup and commands

Run `pnpm install`, copy [.env.example](.env.example) to `.env.local` (git-ignored) and fill in the keys, then run `pnpm dev` and open [localhost:3000](http://localhost:3000). News and QDeal deals come from Supabase, so `pnpm dev` and `pnpm build` need `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` and a reachable project; `next.config.ts` stops with an error without the URL (see [Supabase](#supabase)). A pnpm lockfile is included. `package.json` does not pin a Node engine or package-manager version, but `@supabase/supabase-js` requires Node 22 or later. Epilogue and Bodoni Moda load through `next/font/google`.

Declared versions include Next.js **16.4.2**, React/React DOM **19.3.1**, TypeScript **^5**, Tailwind CSS **^4**, GSAP **^3.15.0**, `@gsap/react` **^2.1.2**, Motion **^14.7.1**, shadcn **^4.22.1**, and `@supabase/supabase-js` **2.118.0** (pinned). See [package.json](package.json) for all dependencies and version ranges.

| Command | Purpose |
| --- | --- |
| `pnpm dev` | Start development server |
| `pnpm build` | Build production app |
| `pnpm start` | Serve production build |
| `pnpm lint` | Run ESLint |
| `pnpm typecheck` | Run TypeScript without emitting files |
| `pnpm format` | Format all TS/TSX files with Prettier; writes files |
| `pnpm import:news` | Upload the seed news photos and upsert the seed posts into Supabase (needs `SUPABASE_SECRET_KEY`); safe to re-run |

## Experience and routes

Every full page load starts with a liquid glass loader (`components/site-loader.tsx`), built on the ReactDrops “Liquid Glass Logo” component (`components/liquid-glass-logo*.{tsx,ts,css}`). The full-screen white overlay renders it at `height: 480` (capped at `100svh`), with `ending="logo"`, `theme="light"` for the light-page optics, `logoColor="original"` so the logo keeps its own black, and `background="#ffffff"`. The logo is `public/loader-logo.svg`. Each pass keeps the component’s look:
- A droplet becomes a sphere, then a rounded glass tile.
- Its wavelength-based bevel refraction bends the logo, with chromatic edge streaks.
- The waves settle, then the glass clears to leave the original logo alone at its normal size, with no wordmark reveal.

The component’s measured responsive fitting sizes the glass to the screen, so it shrinks on phones. While the page loads, `loop` replays the 1.8s entrance after a 1.6s hold on the logo. After hydration, `window.load` and `document.fonts.ready`, looping turns off, so the current pass lands on the logo; a first visit always sees one full entrance. The loader then holds 450ms and fades out over 600ms with a slight scale. It knows the logo has landed through a small local addition to the component: `time()` on its handle, compared with the exported `liquidGlassLogoFinishTime`. A 6s limit covers a renderer that never finishes. When it’s done, the WebGL view unmounts to free the graphics context, and the overlay stays as `data-state="done"`, its state attribute moving `loading` → `finishing` → `leaving` → `done`. The markup is server-rendered, so the white overlay covers the page before hydration. Page scrolling is locked during loading and finishing, and deep links such as `/#visit` still land correctly. Reduced motion shows the finished logo straight away and leaves once the page is ready. Without WebGL2, the component’s image fallback shows the plain logo. A `<noscript>` style hides the loader without JavaScript, and a 12s CSS failsafe hides it if the script never runs. The CSS transition in `globals.css` (`.site-loader`) and `FADE_MS` in the loader must change together.

- `/`: header with the logo at the top left and a fixed main menu at the top right, dithered hero over a faded showroom photo with a today’s-hours glance pill and a “Contact us” link to the footer form, pinned listening story, category explorer at `#categories`, brand wall at `#product-lines`, visit section at `#visit`, and contact footer at `#contact`.
- `/shop/[category]`: artwork, category title, contact action, and return link to the explorer. The 14 slugs in [lib/categories.ts](lib/categories.ts) provide static params; unknown categories return not found. The category artwork loads with `loading="eager"`, since it is the above-the-fold LCP image (a lazy one triggers Next’s dev LCP warning).
- `/shop`: collection placeholder. `/shop?brand=<slug>` selects a logo and removable brand filter from the 23 entries in [lib/brands.ts](lib/brands.ts). Clearing the filter returns to `/shop`; unknown brand values return not found. Filtered pages retain a visually hidden accessible heading to avoid a duplicate visible title. The brand logo also loads eagerly for the same LCP reason.
- `/news`: one-column news feed, newest first, with progressive loading (details below).
- `/news/[slug]`: article pages at the live qaudio.com permalinks. Published posts are prerendered from `generateStaticParams`; posts published later render on first visit. Unknown or draft slugs return not found.
- `/api/news?cursor=&limit=`: JSON feed pages (`{ items, nextCursor }`). Omit `cursor` for the newest cards. `limit` defaults to 3 and allows up to 24. A malformed cursor or limit returns 400.
- `/qdeal`: live deals from Supabase (currently the Sonos closeouts), then Q Audio’s “Proper advice is priceless!” text (details below).

The home page’s main menu (`components/site-nav.tsx`) is the React Bits PillNav, at size `lg` with the light theme, without its logo since the header already shows ours. It lists Home, News (`/news`), QDeal (`/qdeal`) and Used Equipment (`/used`), using the live qaudio.com slugs. Used Equipment doesn’t exist in this prototype yet, so it shows the not-found page until built. The current page comes from `usePathname()` and gets PillNav’s active dot and `aria-current`; pages below a section (`/news/<post>`) keep that section active. Links use Next’s `Link`, and hovering an item rolls in the dark pill fill. The bar uses PillNav’s glass surface with extra frost, set through its CSS variables: a 30px blur (from 20px), saturation lowered to 1.2 so colorful sections behind stay neutral, and a 55% white body. It’s fixed at the top right (`z-index: 50`, under the loader), vertically centered on the logo with the header’s side inset (48px, 30px at 1000px and below, 22px at 600px and below), so it stays in view while scrolling. It sits outside `ScrollExperience`, because the pinned stage must not contain it, and comes right after the skip link in tab order. The fixed `.site-nav` wrapper spans the header beside the logo so PillNav can measure when the items no longer fit and collapse into its menu button with a frosted dropdown (as on phones). The wrapper ignores pointer events; only the pill, button and dropdown take them. The news pages share it through `app/news/layout.tsx`, `/qdeal` renders the same header and footer shell in its page, and the shop pages keep their own header.

The root `<html>` carries `data-scroll-behavior="smooth"`. Since Next 16, Next no longer switches off the global `scroll-behavior: smooth` during client-side route changes unless that attribute is set. Without it, its scroll-to-top on navigation animated, then corrected to the page segment, so a news article opened from far down the feed landed 148px down with the header hidden.

The GSAP/ScrollTrigger story pins the stage while the hero exits and vinyl travels through opening text rows. The record tilts, grows, lands on the turntable, and the tonearm moves into place before the story text fades. Responsive layouts, reduced-motion fallbacks, and section-anchor restoration after pinned layout setup are implemented. Back, forward, and reload also return to the exact scroll position, including mid-story. Browsers restore their offset before the pin spacer exists (≈3.1k px of extra height), so they used to land early, inside the record-player story. [lib/scroll-memory.ts](lib/scroll-memory.ts) therefore saves `scrollY` per history entry in `sessionStorage`, keyed by an id added to `history.state`. After fonts, `load`, and `ScrollTrigger.refresh()`, the scroll experience re-applies it with an instant scroll. A saved position takes precedence over a `#hash`, while a fresh visit or hash link has no saved entry and behaves as before. Saving starts only after that restore, so transient positions during load can't overwrite it. Only history states carrying Next’s `__NA` marker are ever extended, because Next reloads the page when it traverses to a state without it. The brand wall’s plain `<a>` tiles make full page loads, which is where the bug showed. The reduced-motion path has no pin and relies on native restoration. For Safari parity, `.vinyl-surround`/`.vinyl-anchor` use an explicit `height` rather than `aspect-ratio`. WebKit stretched the padded aspect-ratio box when its children used percentage heights, which made the disc an ellipse and shifted every scroll position. The tilt’s 1200px perspective also comes from CSS `perspective` on `.is-scroll-active .vinyl-surround` instead of GSAP `transformPerspective`, because WebKit drew the in-transform perspective less foreshortened, so the record never lay flat on the platter. On phones (≤600px), the story text uses `7.1vw`, weight 500, −0.03em tracking, 1.2 line height, and a word-space gap between row halves. Each row parts at its own word break, and the travelling record (about 17% of the width) shifts sideways to that break. That lets the longer halves use the full width before the record moves to the platter as usual.

All seven in-store record sleeves are always shown in random grid squares around the content, at mixed sizes:
- **Larger sleeves:** four on desktop, 2–3 cells wide, placed first and on diagonal quarters.

- **Phones:** the larger ones are 2 cells and the rest a single cell, usually two large and five small.

Sleeve wear is baked into the dot tones: a faint, uneven ring where the record presses, scuffed edges and light paper grain. Animation frames run only while a wave is moving. Reduced motion skips the wave and the sleeves’ fade-in. Open answer cards float above the grid.

## News

`/news` lists the published posts in Supabase as a single column of cards, newest at the top. It started with the nine posts migrated from https://www.qaudio.com/news (October 2026 back to December 2022). The server renders the first page (`NEWS_PAGE_SIZE` = 3 cards). `components/news-feed.tsx` watches a sentinel below the last card and fetches the next page from `/api/news` once it is within 900px of the viewport. Paging uses a cursor (the last card’s publish time and id), so posts published while someone scrolls can’t duplicate or skip cards. A pulsing skeleton card stands in while a page loads. If a request fails, a “Load more” button retries it. Feed pages carry only card summaries (slug, title, store-time date, cover, and the stored excerpt); article bodies ship only with their article pages, and no client bundle includes them or the Supabase client.

The “News” heading shares its row with a cable (`components/cable-heading.tsx`), drawn like the contact footer’s cable: the same black jacket, gray highlight and soft drop shadow, but ending in a different connector. News gets a banana plug (the speaker-cable connector, with a sprung, bulging pin), and its cable runs in one gentle wave, tilting slightly up into the plug. The cable fills the rest of the row and fades in beside the title (56px fade, 36px on phones). The drawing is anchored at the plug (`preserveAspectRatio="xMaxYMid slice"`), so narrower rows show less cable instead of squeezing the plug. At 640px and below it draws at 70% (the contact cable’s mobile scale), and the heading is now left-aligned there instead of centered, since the row spans the column. The SVG is `aria-hidden`, static, and server-rendered, so it needs no reduced-motion handling. Its 84px-tall canvas leaves headroom for loops, and negative block margins keep that from making the row taller than the title.

The cards (`components/news-card.tsx`) take their look from Cult UI’s [Cutout Card](https://www.cult-ui.com/docs/components/cutout-card), reimplemented locally without the package: a white card with the FAQ pills’ hairline ring and soft shadow, and a 16:10 grayscale photo notched with white tabs that blend into it through the component’s concave corner path. The bottom-left tab holds the date; the top-right one holds the site’s circular icon well with an ↗ arrow. Below the photo are the title and a two-line excerpt (three on phones). The title link stretches over the whole card, so the link’s name is just the title. Hovering lifts the shadow, turns the photo to color with a slight zoom, and turns the arrow well into a small vinyl record: a black disc with fine grooves, a moving sheen and a light center label holding the arrow (`.vinyl` in [news-feed.module.css](components/news-feed.module.css)). The disc fades in and spins at 33⅓ rpm (1.8s a turn) while the card is hovered, then pauses and resumes from the same angle on the next hover. The arrow sits above the disc and stays upright; a small mark on the label edge makes the turning easy to see. Like the other hover effects, it needs a fine pointer, so touch screens keep the plain well. Keyboard focus outlines the card and also shows the photo in color. On touch screens, which can’t hover, the card crossing the middle of the screen is the active one in color. Posters and wide product shots set `fit: "contain"` and sit letterboxed on light gray, their white backgrounds multiplied away. Newly loaded cards fade up with a short stagger.

A year divider (a small tracked label and a hairline across the column, drawn by `YearDivider` in `components/news-feed.tsx`) precedes the first card of each store-time year, including the newest. It’s computed from the loaded list, so pages that arrive later get theirs, and it fades in with its card. Each divider sits closer to its own cards than to the group above. It’s `aria-hidden`, since every card’s `<time>` already carries the full date, so the feed’s accessible children stay just the articles.

The feed uses the ARIA feed pattern: `role="feed"` with `aria-busy` while a page loads, and each card is an `article` with `aria-posinset`, `aria-setsize` and its title as its label. With focus on a card, Page Down and Page Up move to the next or previous card and center it. Loaded cards persist in a module-level cache across client-side navigation, so returning from an article shows the same feed at the same height. The cache is dropped when the server’s first page no longer matches it, for example after a new post. Scroll position reuses [lib/scroll-memory.ts](lib/scroll-memory.ts): after back, forward or reload, the feed fetches the missing cards in one request (the tab’s loaded count is kept in `sessionStorage`), restores the saved position, and only then starts saving again. Reduced motion removes the entrance, skeleton pulse, hover zoom, and the record’s spin (the disc still appears on hover, standing still).

Article pages show a “← All news” link, the full date, the title, the cover at its natural proportions (tall posters capped to the screen), and the body. The body (`components/news-body.tsx`) renders structured blocks (paragraphs with bold text and links, a heading, a list, a pull quote, and captioned images) in a 680px column. The reads are cached with `unstable_cache` under the `news` tag for 5 minutes. `/news` and the article pages regenerate on the same interval (`revalidate = 300`), so changes made in Supabase, including scheduled posts reaching their time, appear within 5 minutes. The admin editor will call `revalidateTag("news")` to show saves immediately. This uses Next’s previous caching model; Cache Components stays off because it keeps hidden pages mounted, which hasn’t been tested against the home page’s pinned GSAP story. The reader turns `published_at` into a store-time (`America/New_York`) date. It resolves media paths to public bucket URLs and checks each body block, dropping malformed ones and any link that isn’t `http(s)`, `mailto:`, `tel:`, or a site path. Until the admin editor exists, add or edit posts in the Supabase table editor: store a body image’s `src` and the cover as paths in the `media` bucket, and write `excerpt` with `newsExcerpt` from [lib/news.ts](lib/news.ts), the rule the import used. ## Supabase

Supabase holds the site’s editable content, images, and admin sign-in. News and QDeal deals are served from it; the admin editor comes next.

- **Project:** `qaudio` (ref `kemumhpxapfadqsytudt`), region `us-east-1` (N. Virginia), Postgres 17. It’s on the Free plan in the Vercel-linked organization “gaiborjosue’s projects”. Free projects pause after a stretch of inactivity, so plan a paid tier before launch.
- **Migrations:** SQL files in [supabase/migrations](supabase/migrations), named `<applied version>_<name>.sql`. They were applied through the Supabase MCP server.
  - `harden_default_privileges`: new tables, sequences, and functions in `public` get no automatic grants for `anon`, `authenticated`, or `service_role`, and functions are no longer executable by everyone. Every exposed object needs an explicit grant plus RLS.
  - `admins_and_news_posts`: an internal `private` schema (not exposed through the Data API) with `private.admins` (one row per admin user) and `private.is_admin()`, which RLS policies call. Admin rights change on the next request, with no stale JWT claims. `public.news_posts` holds slug (the live permalinks), title, excerpt, `body` (a JSON array of the `NewsBlock` blocks in `lib/news.ts`), cover path, size, alt text and fit, `status` (`draft`/`published`), `published_at`, and timestamps. `updated_at` is maintained by a trigger. A partial index on `(published_at desc, id desc)` serves the feed and keyset paging. A published post needs a date and a cover.
  - `media_bucket`: a public `media` storage bucket (images only: WebP, JPEG, PNG, AVIF; 10 MB each), organized by folder such as `news/…`. Anyone can load a file by its public URL; only admins can list, upload, replace, or delete. `next.config.ts` allows `next/image` to optimize files from it.
  - `news_feed_function`: `public.news_feed(after_published_at, after_id, max_rows)` returns published cards (no bodies) after a `(published_at, id)` cursor, newest first, capped at 50 rows. It runs as the caller, so RLS still applies; `anon`, `authenticated`, and `service_role` may execute it.
  - `deals`: `public.deals` (title, summary, note, `status`, `sort_order`, optional `starts_at`/`ends_at`, timestamps) and `public.deal_items` (its products: `deal_id`, brand, name, optional `condition` and `price_cents`, `sort_order`, timestamps), both with the `updated_at` trigger. Products are deleted with their deal, and an index on `(deal_id, sort_order)` serves the foreign key and product order.
- **Access rules:**
  - Visitors read published posts whose `published_at` has passed (a future time schedules a post).
  - Visitors read published deals inside their optional `starts_at`/`ends_at` window, and only those deals’ products.
  - Signed-in non-admins get the same view.
  - Admins read every post and deal and can add, edit, and delete them and their products.
  - Server code using the secret key has explicit grants.

  These were checked by running queries as `anon`, as a signed-in non-admin, and as an admin inside a rolled-back transaction. After the import, the publishable key read the feed in two pages but was refused when updating a post or uploading a file. For deals, visitors and non-admins saw only live deals (not drafts, future or expired ones) and their products, and non-admin writes were refused or changed no rows. The only performance advisory is an informational “unused index” notice for the new `deal_items` index. The only security advisory is leaked-password protection (an Auth setting), which matters only if admins sign in with passwords.
- **Auth:** sign-ups are off and the Site URL and redirect are set to `http://localhost:3000` (Dashboard settings; the production domain comes later). The owner account is the first row in `private.admins`. To make someone else an admin, invite them under Authentication → Users, then add their user id to `private.admins`.
- **Seed and import:** [supabase/seed/news.json](supabase/seed/news.json) holds the migrated posts in table form, and [supabase/seed/news](supabase/seed/news) holds their 20 photos. [scripts/import-news.mjs](scripts/import-news.mjs) (`pnpm import:news`) uploads the photos to `media/news/` (one-year cache, since names never change) and upserts the posts by slug as published. It uses the secret key, which bypasses RLS, so run it only from a trusted machine. The live feed showed times without a time zone; the seed treats them as Eastern (`-04:00`/`-05:00`), and only dates are displayed. The two posts stamped Jan 29, 2026 4:27 PM got seconds (`:30` and `:00`) to keep their live order. [supabase/seed/deals.sql](supabase/seed/deals.sql) inserts the current closeout deal and its four products with fixed ids; it was run once through the MCP server. Rerunning it (SQL editor or MCP) skips rows that already exist, so it won’t undo later edits.
- **Keys:** `.env.local` holds the project URL and publishable key, which are public by design, and `SUPABASE_SECRET_KEY`, which is server-only. The secret key is used only by the import script; no app code reads it. Never commit it, give it a `NEXT_PUBLIC_` prefix, or share it in chat.
- **Types:** [lib/supabase/database.types.ts](lib/supabase/database.types.ts) is generated from the schema (Prettier skips it). Regenerate it after schema changes.

Brand filtering currently changes destination branding rather than filtering a product catalog. Store hours and schedule changes are edited in code; there is no owner-facing editor yet. News posts and QDeal deals are edited in the Supabase table editor until the admin editor exists. If Supabase is unreachable or the Free-plan project is paused, `/news`, article pages and `/qdeal` keep serving their last generated version, but loading more news cards fails to the “Load more” button and `pnpm build` fails. News posts’ product links still point to `https://www.qaudio.com/products/…` pages from the current site, which this prototype doesn’t have, so they need redirects or new destinations before the domain moves. QDeal’s client-side “visit us” link lands on the home page’s visit section, but the pinned story can flash for a few frames on the way while its layout sets up. When a back, forward, or reload restores the feed far down, a lazily loaded card can become the LCP image, and Next’s dev LCP warning names it. Live hours status depends on the visitor’s device clock. Browser audio policies can suppress the tick, and glass rendering varies across browsers. Source inspection alone does not certify cross-browser visual behavior.
